## 背景

目前产品是命令行脚本（`run_e2e.py`），目标用户（自媒体、课程团队）不会用终端。海风声影的卖点之一是"无需配置、解压即用、一个工作台完成全部流程"。本计划构建 Tauri 桌面壳：GUI 导入视频 → 后端排队处理 → 实时进度 → 成片预览/导出。

## 目标与范围

**范围内**：
- Tauri v2 桌面壳（Rust + Web 前端），跨平台骨架
- Python FastAPI 后端：任务队列 + 进度上报 + 调用现有 pipeline
- GUI 基本流程：选视频 → 选模式（自动/多角色）→ 进度条 → 输出路径
- 后端作为子进程由 Tauri 拉起（含 venv 路径解析）

**范围外**（后续里程碑）：
- 手动模式（音色/角色手动指定）——0006 或之后
- 音色库管理、批量队列、会员/水印
- 打包分发（绿色版/安装包）——产品化阶段（0007+）

## 决策日志

- **2026-08-04**：后端用 FastAPI（AI 生态已在 Python），Tauri 只做壳与进程管理——避免在 Rust 侧重复实现 pipeline。
- **2026-08-04**：进度上报用 SSE（单向、简单），不引入 WS 依赖。
- **2026-08-04**：后端地址固定 `127.0.0.1:<随机端口>`（Tauri 启动时分配），避免端口冲突。
- **2026-08-04**：前端用 Vanilla HTML/CSS/JS，由后端直接托管静态文件（`/` 返回页面），浏览器可测，Tauri 只是加载该 URL——无需前端构建链。
- **2026-08-04**：DeepSeek API Key 通过 GUI 配置，持久化到 `workdir/settings.json`（gitignored），后端任务运行前注入环境变量。
- **2026-08-04**：本机 `all_proxy=socks://` 前缀 httpx 不识别（T-003）——后端任务运行前清理 socks:// 代理，DeepSeek 可直连。
- **2026-08-04**：进程生命周期用**父进程看门狗**（Tauri 传 `--parent-pid`，后端轮询父进程存活，父进程死亡则自杀）——比依赖 Tauri RunEvent::Exit 更可靠（SIGTERM 下 GTK 不保证优雅退出），已验证杀应用后无僵尸后端。
- **2026-08-04**：`launch_server.py`（双 fork 守护化）保留用于开发调试场景，Tauri 壳直接前台启动 `server.py`。
- **2026-08-04**：真实发现 bug——`settings.py` 用非可重入 `threading.Lock`，`save()` 内调 `load()` 死锁导致 POST /api/settings 挂起。修复为 `RLock`。

## 风险

| 风险 | 对策 |
|------|------|
| Rust/cargo 未安装或版本旧 | 检查后用 rustup 安装稳定版；Tauri v2 需要 Rust ≥1.77 |
| Tauri 系统依赖（webkit2gtk 等）缺失 | Linux 需 `libwebkit2gtk-4.1-dev` 等，文档化安装命令 |
| 后端子进程 venv 路径在打包后变化 | 抽象为配置（开发=本地 venv，打包=内嵌 Python）；本计划先做开发模式 |
| 前端框架选择（React/Vue/Svelte） | 选最简（Vanilla TS 或 Svelte），UI 复杂度低 |
| GUI 任务阻塞/无进度反馈 | SSE 进度 + 取消按钮（后端任务可中断，0001 已留状态机） |
