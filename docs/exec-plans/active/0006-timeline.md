# 执行计划 0006：弹性时间轴 + 长停顿剪辑

> 状态：📝 起草中（0005 完成后启动）
> 创建：2026-08-04
> 前置：0001-0004（pipeline 完整）、0005（桌面壳）
> 目标：实现海风声影的核心卖点——**中文配音优先自然语速**：弹性时间轴对齐（不强行压缩/拉伸）、自动检测并裁剪长停顿/静音，让成片"听起来像中文母语者在说话"。

## 背景与问题

当前混音（step4_mux）用 `adelay + amix` 把译文语音**按原时间轴硬对齐**。中文与英文时长差异很大（中文通常更短），导致三种听感问题：

1. **语速异常**：译文长于原时段 → 被压缩 → 说话像开倍速
2. **忽快忽慢**：逐句硬对齐，句间节奏不连贯
3. **突兀停顿**：译文短 → 句间出现大段静音 → 节奏拖沓

海风声影的解法："**目标不是机械地追求每一句时长完全相同，而是在中文听感、时间同步与画面节奏之间取得更自然的平衡**"——优先保证中文自然语速，再用弹性时间轴 + 静音剪辑补偿。

## 目标与范围

**范围内**：
- **弹性时间轴对齐**：译文语音按"语速自然"优先放置，允许与原时间轴偏差
  - 变速补偿：±15% 内（高质量变速，rubberband/atempo）
  - 偏移补偿：整段平移 + 相邻段空隙吸收
- **长停顿检测与剪辑**：>1.5s 静音自动裁剪 + 交叉淡化过渡
- step4_mux 升级 + run_e2e 集成开关（`--elastic-timeline`）
- 客观 + 主观验证

**范围外**：
- 画面级剪辑（裁帧/转场）——仅音频时间轴
- 口型同步（Wav2Lip）
- 自动字幕重排（字幕跟随新时间轴，含）

## 技术方案

### 弹性对齐算法（草案）

```
输入：分段列表 [{id, orig_start, orig_end, zh_audio_path, zh_duration}]

1. 计算每段时长差：delta_i = zh_duration_i - (orig_end_i - orig_start_i)
2. 变速决策：
   - delta_i > +15% × orig_duration  → 变速到 1.15x（限幅）
   - delta_i < -15% × orig_duration  → 变速到 0.85x（限幅）
   - 其余 → 不变速（自然语速）
3. 放置：
   - 变速后的段按原 start 放置
   - 累积偏移 offset：段间空隙 = 原空隙 + 前段时长差
   - 若 offset 使段超出原 end 太多（>300ms），整段向后推移到空隙中
4. 停顿裁剪：
   - 检测合成轨 >1.5s 连续静音
   - 裁剪至 0.8s + 50ms 交叉淡化
5. 输出：新时间轴 + 合成音频 + 字幕（按新时间轴）

约束：全局偏移 ≤ 2s；单段偏移 ≤ 500ms（避免画面-声音明显错位）
```

### 变速实现

- 首选：ffmpeg `rubberband`（高质量，保音色）——需编译支持，检查可用性
- 备选：ffmpeg `atempo`（内置，质量尚可）
- 评估：小样本 A/B 听感

## 风险

| 风险 | 对策 |
|------|------|
| rubberband 不可用 | 退 atempo；若质量不达标，pip 装 pyrubberband |
| 弹性对齐导致画面错位 | 全局偏移 ≤2s、单段 ≤500ms 硬约束；验证时主观检查 |
| 交叉淡化产生杂音 | 用 50ms 短淡化 + 过零检测 |
| 多角色成片时间轴复杂 | 先单人验证，再 multi-speaker 回归 |
| 字幕与新时间轴不同步 | 字幕按新时间轴重新生成（make_srt 复用） |
