# 执行计划 0010：本地翻译引擎接入（零云端依赖）

> 状态：📝 起草中
> 创建：2026-08-05
> 关联债务：T-002（翻译用 DeepSeek API 联网，本地 Qwen 未验证）
> 目标：接入**本地翻译引擎**（Qwen GGUF），让翻译环节也完全离线——兑现"素材不出本机、零云端 API 依赖"的核心产品卖点。翻译引擎变为可切换：`本地(Qwen) / 云端(DeepSeek)`。

## 背景

产品核心卖点之一："核心 AI 全部本地运行、零云端 API 依赖"。目前：
- 识别 ✅ 本地（faster-whisper）
- 音色克隆 ✅ 本地（GPT-SoVITS）
- 说话人分离 ✅ 本地（diarize）
- **翻译 ❌ 依赖 DeepSeek API（联网）** ← 唯一缺口

接入本地翻译后，全链路离线可用，隐私完全不出本机。

## 目标与范围

**范围内**：
- 本地翻译引擎选型与接入：Qwen2.5 GGUF（llama.cpp 系）或更快的小模型
- 翻译 provider 抽象：`本地 / DeepSeek` 可切换（复用现有 providers 架构）
- 字幕翻译场景优化：术语表生效、短句批处理、长度约束
- 验证：中英互译质量、速度（CPU 可接受范围）

**范围外**：
- GPU 加速翻译（用户在 5060Ti 上自然加速）
- 翻译记忆/缓存（跨任务复用）
- 更多语言模型（先中英）

| 方案 | 模型 | 内存 | 速度(CPU 16核) | 质量 | 备注 |
|------|------|------|---------------|------|------|

| B. Qwen2.5-3B GGUF Q4 | ~2GB | ~3-4GB | 20-40 tok/s | ⭐⭐ | 更快，质量稍逊 |

**初选**：A（Qwen2.5-7B Q4）为主，B 作轻量选项。实测质量与速度后定。

## 决策日志

- **2026-08-05**：选 llama-cpp-python（CPU 友好，GGUF 生态成熟，可平滑迁移 GPU）。
- **2026-08-05**：模型下载走 hf-mirror（`--noproxy`，复用 0001 经验）。

## 风险

| 风险 | 对策 |
|------|------|
| 14GB 内存跑 7B 偏紧（whisper 同时占用） | 按需加载模型，翻译完成即释放；或降级 3B |
| 本地翻译质量不及 DeepSeek | 保留双模式，默认仍可选手动联网 |
| llama-cpp-python 编译/依赖问题 | 用预编译 wheel；不行换 llama.cpp 二进制 |
| 翻译速度慢影响体验 | 批处理短句 + 进度提示；GPU 机器自然加速 |
